# PARTE C — Questões de síntese

# 1. O campo PPID em /proc/$$/status indica o processo pai do shell.
#    Execute ps -o pid,ppid,cmd e localize o par shell -> processo pai.
#    O que esse encadeamento sugere sobre como os processos sao
#    criados no Linux?

Resposta 1:
Todo processo no Linux vem de outro processo, como uma árvore genealógica.Nenhum processo nasce do nada, e todo filho herda as configurações do pai — permissões, arquivos abertos, variáveis de ambiente. Se o pai "morre" antes, o filho é adotado pelo PID 1 (o init), que é a raiz de tudo.

# 2. O arquivo /proc/<PID>/status mostra o campo State com uma letra
#    (S, R, Z...). Depois de executar kill $FILHO e rodar ps novamente,
#    o que aconteceu com o processo filho? O que isso te faz pensar  
#    sobre a vida de um processo?

Resposta 2:
Após o kill, o filho pode sumir da lista ou virar um Zombie (Z) — que é quando o processo já morreu mas o pai ainda não "reconheceu" a morte dele. Ele fica preso na tabela do kernel como um fantasma, sem consumir recursos mas sem desaparecer de vez.
Isso faz pensar que a vida de um processo tem um ciclo completo:
nasce → executa → morre → espera o pai "enterrar" ele 
A lição principal é: um processo não tem autonomia nem na morte — ele depende do pai para sumir de vez. Se o pai nunca chamar wait(), o zombie fica preso até o PID 1 assumir a responsabilidade.
